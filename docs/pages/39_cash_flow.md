# Cash Flow

Route `/reports/cash-flow` (`src/App.tsx:519-526`, lazy import `src/App.tsx:46`, listed in the `BUILT` set at `src/App.tsx:783`) · component `src/modules/reports/CashFlowReport.tsx` · 323 lines.

## 1. What it is

A one-month cash statement plus a profit-to-cash reconciliation, rendered entirely from constants and pure functions in `src/data/liquidityReports.ts` (imported at `CashFlowReport.tsx:10-28`; the file imports no query module — see its full import block, `CashFlowReport.tsx:1-28`).

Its own header states the two rules it exists to carry: deposits never enter a cash total and the report is cash basis, both enforced in the data file rather than the screen (`CashFlowReport.tsx:40-45`; `liquidityReports.ts:12-23`, `netCash()` at `liquidityReports.ts:76` sums `CASH_LINES` only and cannot reach `DEPOSITS_HELD`).

The whole body is gated on `useCanViewMoney()` — a money-blind session gets the shared RESTRICTED state and nothing else is built (`CashFlowReport.tsx:117`, `:122-135`).

## 5. Gates

**Route reachability.** `/reports/cash-flow` is inside the `/reports` prefix in `MONEY_ROUTES` (`src/data/nav.ts:147-153`, matched by `isMoneySurface`, `:156-159`). `Shell` computes `isForbidden = !canViewMoney(user.role) && isMoneySurface(pathname)` (`src/App.tsx:993`) and renders `RestrictedState` in place of the page when true (`src/App.tsx:1020-1023`). Unauthenticated visitors are redirected to `/login` before that (`src/App.tsx:973-975`).

**Which roles reach it.** `canViewMoney` is `!MONEY_BLIND.has(role)` and `MONEY_BLIND` is `Warehouse · Technician · Driver · Client` (`src/lib/rbac.ts:36-38`, `:45-50`) over the nine `SystemRole` members (`src/types/database.ts:116-125`). So **Owner, Admin, Manager, Coordinator and Accounts** reach the page; **Warehouse, Technician, Driver and Client** are stopped by the Shell guard.

**Money visibility (Law 6).** The page calls `useCanViewMoney()` at `CashFlowReport.tsx:117` — `useAuth().user ? canViewMoney(user.role) : false` (`src/lib/moneyVisibility.ts:24-27`). When false it returns the `PageHeader` plus `PageBody restricted` and `{null}` for children (`CashFlowReport.tsx:122-135`), so **the entire body — KPI strip, toolbar, statement, reconciliation and footer — is absent from the DOM rather than masked**, which the file states as a deliberate deviation (`CashFlowReport.tsx:52-53`).

**What is hidden under Law 6:** everything except the `<h1>`, the "Finance ▸ Reports" description, and the restricted card. Nothing is masked or blurred; no figure is emitted for a money-blind session. Note that this in-page branch is defence in depth only — see §7, gap 1.

## 7. Known gaps

1. **The page's own Restricted state is unreachable through its route.** `isMoneySurface('/reports/cash-flow')` is true (`src/data/nav.ts:147-159`), so the Shell guard returns `RestrictedState` before the component mounts for every money-blind role (`src/App.tsx:993`, `:1020-1023`), and unauthenticated users are redirected at `src/App.tsx:973-975`. The component is mounted from exactly one place (`src/App.tsx:523`). The branch at `CashFlowReport.tsx:122-135` therefore cannot render as the app is wired today, and the restricted copy a money-blind operator actually sees is the Shell's generic sentence, not this page's specific one.
2. **The restricted chip names four roles; five roles can see money.** `restrictedRequiredRole="Owner, Admin, Coordinator or Accounts"` (`CashFlowReport.tsx:129`) omits **Manager**, who is not in `MONEY_BLIND` and passes `canViewMoney` (`src/lib/rbac.ts:45-50`). An operator told to ask an Admin could equally ask a Manager.
3. **Two KPI deltas are invented in the page file.** "2% vs last month" (`CashFlowReport.tsx:157`) and "0.2 mo vs last month" (`:183`) are string literals with no source; there is no prior-period data anywhere in `src/data/liquidityReports.ts`. This contradicts the file's own stated rule three lines up from where they sit — *"a sentence with a number in it is a calculation, and calculations belong to the engine"* (`CashFlowReport.tsx:49-51`) — and the same rule is why `collectionUpside(80)` was moved into the engine (`liquidityReports.ts:93-98`).
4. **The prose decomposition of the gap does not match the arithmetic.** `CashFlowReport.tsx:231` states "The {gap} gap is receivables plus capex". The gap is `PAPER_PROFIT − netCash()` = Rs 2,29,000 − Rs 83,000 = **Rs 1,46,000** (`liquidityReports.ts:91`), which is exactly `uncollected()` = Rs 4,20,000 − Rs 2,74,000 = Rs 1,46,000 (`liquidityReports.ts:84`). Receivables **plus** the Rs 56,000 capex line (`liquidityReports.ts:47`) would be Rs 2,02,000. The sentence names a decomposition the constants do not produce.
5. **"BS" is printed twice in the period line.** `formatBs(bsStart)` is called with no options and `formatBs` defaults `suffix` to on (`src/lib/bs.ts:102-105`), so `CashFlowReport.tsx:140` renders "1 Shrawan 2083 **BS** – 31 Shrawan 2083 **BS**". The shared toolbar formats the same pair with `{ suffix: false }` on the leading date for this reason (`src/components/ui/ReportToolbar.tsx:281`).
6. **The reported period runs 15 days past the app's operating day.** `PERIOD_END` is 15 Aug 2026 (`liquidityReports.ts:30`) while the app's single `TODAY` is 31 Jul 2026 (`src/lib/bs.ts:153`). The page presents it as a closed month ("The month was cash-positive", `CashFlowReport.tsx:213`) and states a 3.1-month runway from a balance that is two weeks in the future relative to every other date in the product.
7. **Two different Cash Flow reports exist, over two independent invented ledgers.** `src/modules/reports/catalog.ts:239` registers `cash-flow` with `projection: 'cash'`, whose source is declared as *"data/pulse.ts — LEDGER cashIn / cashOut, via figuresFor(from, to)"* (`catalog.ts:143-149`). That register is rendered inside the Finance ▸ Reports tab (`src/modules/finance/Finance.tsx:1042`): clicking the row name calls `onOpen` (`src/modules/reports/ReportCatalog.tsx:547`, `:254`) → `setOpenReport(r)` → `<ReportTemplate>` over the pulse projection (`ReportCatalog.tsx:153`, projection read at `src/modules/reports/ReportTemplate.tsx:123-132`), while the arrow beside the same row links to this screen (`ReportCatalog.tsx:580-584`). The two answer the same question from different constants: `data/pulse.ts` builds `cashIn`/`cashOut` per day from a generated ledger (`src/data/pulse.ts:260-305`), and its coverage ends at `LEDGER_TO = TODAY` = 31 Jul 2026 (`src/data/pulse.ts:48-50`) — so it cannot even span this page's 16 Jul – 15 Aug period. The catalog file's own premise is that the 43 reports share one figures source (`catalog.ts:8-18`); this route does not use it.
8. **Pulse's Cash KPI links here from a different number.** `Pulse` renders a "Cash" card whose value is `formatMoney(figures.collected)` from `data/pulse.ts` and whose action is "Open Cash Flow report" → `/reports/cash-flow` (`src/modules/reports/Pulse.tsx:561-572`). The destination's "Cash collected" is `cashIn()` = Rs 2,74,000 from `CASH_LINES` (`liquidityReports.ts:45`, `:68`). Same label, two unrelated sources.
9. **The period control cannot exist while the source is a constant** — stated in the file rather than left implicit (`CashFlowReport.tsx:195-201`): `liquidityReports` holds one closed month and its engine functions take no range, so a picker would relabel the page and move no figure. Recorded here as the structural gap it is, not as a defect in the toolbar wiring.

Neither is reachable from this page — it never sets `loading` and draws no date control.
11. **No test covers this screen.** `src/modules/reports/__tests__/` holds `catalog.test.ts`, `ExpenseReports.toolbar.test.tsx`, `payables.test.ts` and `ReportCatalog.dedup.test.tsx`; `payables.test.ts:14` imports `liquidityReports` but asserts the working-capital/payables side (`payables.test.ts:22`).
