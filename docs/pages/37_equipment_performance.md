## 1. What it is

A read-only fleet report: four headline cards and two five-column tables, every figure printed from one constant module — `src/data/equipmentPerformance.ts`, imported at `EquipmentPerformance.tsx:5`.

It queries nothing. The component's imports are five UI/lib modules plus that one data module (`:1-8`); there is no `lib/queries/*` import, no `useList`, and nothing from `src/actions/`.

Two of the four headline cards deliberately print "Not tracked yet" instead of a number — ROI and payback period, because nothing in the repo records what a unit cost (`:109-127`, and the deletion note at `src/data/equipmentPerformance.ts:3-13`). The only behaviour that does real work is export: `ReportToolbar` is handed a `csv` spec (`:99`) whose `build` serialises the same constants (`:28-54`).

## 5. Gates

## 7. Known gaps

1. **`TODO(decision)` markers in this file: none.** The two unsourced figures are handled the other way instead — stated on screen as "Not tracked yet" with the missing column named (`:109-127`), and deleted from the data module rather than left exported (`src/data/equipmentPerformance.ts:3-13`). The ROI/payback gap itself is unresolved: no migration provides a purchase-cost column.
2. **The restricted panel names the wrong role set.** `restrictedRequiredRole="Owner, Admin, Coordinator or Accounts"` (`:77`) omits **Manager**, whom `canViewMoney` admits (`rbac.ts:45-50`). Five roles pass the gate; the chip names four. Identical defect on the sibling report — `PromotionsReports.tsx:70` (see `docs/pages/34_promotions.md` §7 gap 11).
3. **The page's restricted branch is unreachable at this route.** `Shell` substitutes its own `RestrictedState` on the identical predicate before the component mounts (`App.tsx:993`, `:1020-1023`; `nav.ts:147-159`), so `:70-83` — and the more specific reason string it carries — can only be seen if this component is mounted somewhere outside `/reports`.
4. **`PerfKpiCard` is `({...}: any)` and silently drops `icon`.** The props are untyped (`:10`); `icon` is passed on all four cards — `dollar`, `chart`, `clock`, `alert_triangle` (`:106`, `:117`, `:125`, `:132`) — and the component never renders it (`:11-17`). The shared `KpiStrip`, which does draw an icon tile and applies the same column clamp, exists at `Page.tsx:203-304` and is not used.
5. **Three of the card's colour tokens do not exist.** `PerfKpiCard` sets `background: var(--${accent}-bg, var(--card))`, `color: var(--${accent})` and `color: var(--${note.tone})` (`:12`, `:14`, `:15`).
   - `--primary-bg`, `--neutral-bg`, `--warning-bg` are undefined in `src/styles/theme.css`, so the declared `var(--card)` fallback always wins and **all four cards share one background** — the accent is invisible. (`App.tsx:819-823` records the same finding for `--warning-bg` independently.)
   - `--neutral` is undefined too — only `--st-neutral-bg` / `--st-neutral-fg` exist (`theme.css:129`, `:255`) — so the ROI and Payback values (`accent="neutral"`, `:118`, `:125`) and the Equipment Revenue note (`tone: 'neutral'`, `:107`) resolve to an invalid declaration and inherit the surrounding text colour instead of the muted one intended.
   - The tokens that do resolve: `--primary` (`theme.css:47`, `:188`), `--warning` (`:43`, `:186`), `--danger` (`:44`, `:187`), `--text2` (`:82`, `:214`).
6. **The entire report body is passed to `ReflowRail`, which at ≥ 1180 is a 288px collapsible rail.** `ReflowRail` (`:137-191`) → `Rail` → `CollapsibleAside width={288}` with `position: sticky`, `max-height: calc(100vh …)` and its own inner scroll (`Page.tsx:349-366`, `:315-331`, `CollapsibleAside.tsx:155-183`). This page has no `content | rail` grid to put that rail beside — the container at `:86` is a plain flex column and `useRailGridColumns` (`Page.tsx:382`) is not imported. So at desktop both five-column tables render inside one 288px sticky, self-scrolling column, and gain a collapse handle that can hide the whole report. Below 1180 the rail reflows to a full-width column and the layout is correct. Compare the reports that use the documented pairing: `ExpenseReports.tsx:182` + `:536`, `CashFlowReport.tsx:116` + `:306`, `ClientReports.tsx:177` + `:431`. Not unique to this page — `PromotionsReports.tsx:126`, `StaffReports.tsx:132`, `InventoryReports.tsx:102` and `ForecastingReports.tsx:118` repeat the same shape.
7. **Both tables stay tables below 768.** `useTabularLayout()` (`device.ts:139-141`) is not consulted, so the five-column tables (`:141-162`, `:167-188`) render unchanged at phone width. They carry no `minWidth` and no `overflow-x` wrapper, so the columns compress rather than scroll — the opposite failure from the `minWidth: 900` tables `device.ts:1-20` describes, but the same unread rule.
