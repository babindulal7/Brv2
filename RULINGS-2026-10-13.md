# Rulings — 13 October 2026

## Client CSV import and shortage drill-downs

User instruction: apply the useful improvements from the supplied scrape archive, then continue.

- Client CSV import saves supported identity/contact/address/registration/note fields through the existing `save_record_editor` transaction. It creates records only; existing clients are never overwritten or merged. Membership remains in its existing workflow. Omitted type/subtype/country use the shared client-form defaults; invalid supplied enums are rejected.
- The import surface and action use the intersection of `client.create` and full client-contact access (Owner, Admin, Manager, Coordinator). Warehouse retains walk-in creation. Accounts retains reads without creation. No database grant or capability is widened.
- Every included row has an immutable save request and UUID while the import remains open. Retries reconcile existing receipt keys and skip already-confirmed rows. A timeout is unconfirmed, never success; subsequent rows wait. Each confirmed row uses the existing transactional audit. Progress counts confirmed writes only. Mapping collisions, malformed input, repeated phone/email rows and existing matches must be resolved or explicitly excluded before saving; nothing silently collapses by name.
- Shortage date ranges include the configured operational day, with a half-open end after the final selected day. Calendar links use the peak instant's Nepal civil date. Existing stock-ceiling arithmetic and limitations remain. An unreadable live hold produces an error rather than an empty result.
- Existing rental visible-column CSV behavior and deposit separation (7 October) remain. Export audit metadata now identifies selected page rows, a current page or the loaded client directory. No all-matching export or broader data access was introduced.

Sources: `docs/PERMISSIONS.md` §3.1 C5/W10 and §4.5, RULINGS-2026-10-06, 2026-10-07 adoption row 12, migrations 0146/0153, shared `recordDefaults.client` and operational-day engine. No new migration, live apply or production write.

Revert: restore ImportCenter's validation-only commit area; remove the import action and its menu gate. Restore the previous shortage range/link rendering and remove export scope metadata. Retain existing client records and audits.
