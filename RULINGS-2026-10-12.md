## Shared header ownership and browser acceptance

User instruction: implement the pasted one-header UX fix and functional acceptance plan.

- The authenticated workspace uses the existing application header at 64px, including phones. Its controls have at least 44px targets. Page action portals own the right-hand controls and suppress the shell's fallback Add before paint; registered primary/legacy actions also suppress that fallback.
- Rentals has one New Rental creation action. Fast Return and Record Payment appear once in More, with existing permissions and callbacks. Phone Filters appear in More, and the page search owns the phone search trigger. The unavailable Duplicate Rental placeholder is removed from the menu.
- Team internal notes move into the phone profile menu; Alt+N remains. Phone title width can shrink to keep actions within the viewport. Page information remains available through the existing page information affordance.
- Shared PageHeader registration depends on stable context setters. Metadata changes update the header without clearing it; unmount releases it. Depending on the context object caused repeated registration/cleanup and a browser update loop.
- Existing operation callbacks and legacy header APIs remain. Their consolidation, every-page functional acceptance, native 125% zoom, all-role browser testing and staging JWT/PostgREST verification are subsequent acceptance work; local checks cannot certify production readiness.
