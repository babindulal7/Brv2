## R-23 — PERMISSIONS.md is wired into PLAN.md, and its own supersession sweep is scoped down

**Decision.** `docs/PERMISSIONS.md` is now reachable from where sessions actually start reading,
and the one instruction in it that would have destroyed better information than it replaced is
scoped so nobody carries it out later.

**Placed:**

1. **`PLAN.md` §0**, immediately after the seventeen laws — a paragraph naming PERMISSIONS.md as
   the single authority for who may do what, stating that its P1–P10 sit *beside* the seventeen
   rather than replacing them, and pointing at §16 for where it is known to be wrong. PLAN.md is
   step 1 of `CLAUDE.md`'s read-first order, so this is the placement that makes the document
   findable at all. Nothing in PLAN.md was rewritten.
2. **`CLAUDE.md`** already carries §15 verbatim under "Authority to resolve conflicts" (7 Sep,
   commit `4c35d98`), as §15.5 requires.
3. **`docs/pages/INDEX.md`** — a cross-reference stating the relationship in both directions.

**Scoped down — the sweep §0 asks for is not performed:**

§0's Authority row says every role/permission table in a module spec "becomes one line:
*Permissions: see PERMISSIONS.md §4*". Checked before acting:

- Every spec it names by title — Foundation, Administration v3.1, Crew v3.2, Handover v1.1,
  Finance v2.1, the 22 Jul RBAC grid — lives in `ARCHIVE/mds and photos/`, **outside this repo**.
  There is nothing tracked here to rewrite, and being in `ARCHIVE/` already retires them.
- The one in-repo set that resembles a target is `docs/pages/*.md` — 25 of its 56 files carry a
  role table. **It is not a target.** Its own INDEX states its purpose: *"recording what the code
  does, not what any spec intended… Nothing in this pack is taken from PLAN.md or any spec file"*,
  and every predicate it names carries a `file:line` (e.g. `28_finance.md` §5: `canTakePayment` →
  `canRecordPayment`, `rbac.ts:296-299`, Owner · Coordinator · Accounts).

So the sweep would have replaced the repo's **most accurate** permission information with a
pointer to a catalogue that §16 measured at **26% accurate against that same code**. Per §15.1
B-1 the stricter, better-evidenced side wins, and per §0's own caveat a source that is *more*
correct is not overwritten by this document. The Gates sections keep their tables and gain a
cross-reference; §0's Authority row now carries the scope inline so the sweep is not attempted.

**A use this turns up:** fixing §4's catalogue should start from `docs/pages/*` §5, because those
tables already name the real predicates with line numbers — the work §16 V-1 describes is largely
transcription from there, not fresh discovery.

**Revert.** Remove the PLAN.md paragraph, the INDEX.md cross-reference and the ⛔ scope note in
§0's Authority cell — three deletions, no code. Reverting restores an instruction that would
delete `docs/pages/*` §5 Gates tables, which is why it is written down rather than silently
dropped.
