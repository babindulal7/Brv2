# Rulings — 7 October 2026 UI/UX audit

## User ruling

The user explicitly selected **Restore the locked 11-item navigation**: New Rental · Today · Operation · Rentals · Calendar · Crew Assist · Inventory · Clients · Finance · Tools · Settings. Documents and Analytics remain within Finance. `src/data/nav.ts` records the ruling at the implementation site. `/dashboard`, `/documents`, `/reports` and legacy action routes retain compatible destinations.

## Today color direction

The user requested "colorize the today page smartly." Blue identifies dispatch/pickups, green identifies returns and amber identifies upcoming packing. Soft surface tints, thin borders and section labels carry category color. Zero/unknown figures retain neutral text and icons; the overdue card gains red only when its live count is positive. Existing light/dark theme tokens are reused, scoped to Today. Missing Shift Handover information remains neutral. Implementation: `Today.tsx` overview accents/state and the ruling comment in `dashboard.css`.

## New Rental reorganization

The user requested "re organize ne rental page." Keep one continuous booking form: Client and Rental period, then Equipment, Bundles & Services, optional Crew and Delivery, then open Pricing & Terms. Dates come before their shortcuts; start-day and duration remain separate. Shoot presets stay behind their disclosure. Container queries use the available form width to balance the first row and pair optional logistics, then stack when space is limited. Desktop summary has its own scroll area above the action footer; below 1280 it remains inline. Phone actions place Save draft beside the wide confirmation button, with Cancel, save state and Summary above. Existing fields, draft restoration, validation, role gates and write paths are preserved. Implementation comments: `NewRental.tsx` and `new-rental-flow.css`.

## Global font clarity

The user reports blurry text and requests a global sharpness change. Keep the existing application font families. Load real Source Sans 3 medium (500) and bold (700) faces alongside existing weights, use medium as the regular body default, prevent synthesized bold while retaining italic styling, and return platform smoothing to native defaults. Shared UI/meta/caption size tokens round to whole CSS pixels when supported, with the existing rem scale as fallback; browser/user scaling and floor/wall sizing remain. Page entrance animations release their transform after completion instead of retaining their final animation state. This is an application typography adjustment, not an OS/display setting change. Implementation comments: `main.tsx`, `theme.css`, `ui-v2.css`.

## Content hidden behind the shell

The user highlighted the Add item to booking panel and requested checking content hidden behind the shell. The inline catalogue expands within Equipment instead of floating outside its clipped card. Scroll the workspace to the section heading; keyboard navigation scrolls only catalogue results, accounting for sticky group headings and tall rows. Measure catalogue height against the actual booking action bar, and wrap phone item headings before status/rate chips. Shared overflow menus, including excess PageActions, use fixed body portals with viewport bounds; preserve outside-click, keyboard and action behavior. Select menus fit their available viewport space. Select/date/time body portals render above their owning modal through the existing layer tokens. Keep intentional shell/card overflow containment. No business logic, persisted record, role gate or migration changes. Details and evidence: `docs/SHELL_CLEARANCE_AUDIT_2026-10-07.md`; implementation comments in AddItemPanel, useFloatingMenu and floatingLayer.

## New Rental field and summary refinements

The user's three annotated comments are binding: Client History becomes an icon inside the client search field; Discounts & Taxes precedes Rental Charges (left on desktop, first when stacked); remove the right-hand summary collapse control everywhere. Keep the existing history panel and health quick view, pricing handlers, security deposit policy and role gates. The shared Rail stays visible even when an older per-route preference was collapsed; it keeps desktop sticky scrolling and responsive reflow. Left filter rails, main navigation and form section disclosures retain their controls. Implementation comments: BookingClientSection.tsx, RentalPricingSection.tsx and Page.tsx. No live records or schema changes.

## Booking dates use orange

The user highlighted both Pickup and Return in New Rental's summary and ruled that booking dates should be orange everywhere. Use the shared --booking-date-text token for booking schedule dates and times in New Rental, rental lists/cards/details, floor operation summaries/shells, calendar booking details, client rental history, hover/Intel details, extension and vendor return-by displays. BsAdDate has an explicit booking tone; DateField has an explicit bookingDate flag, leaving non-booking dates at their existing colors. Light theme uses deeper orange ink (#985014) to clear 4.5:1 on its darkest inset; dark inherits the theme's orange text. Preserve date engines, labels, missing-value states, financial dates, role gates and write paths. Implementation ruling comment is in theme.css. No record or schema change.

## New Rental spacing and required labels

The user accepted the recommended next pass on top spacing and required-field clarity. Remove stacked margins between the recovery banner and setup, reduce banner/header padding, and keep recovery actions grouped with 44px targets. Mark Client, Project Type (including Other's specification) and pickup/return date-time values as required to confirm; remove misleading stars from optional Manual Discount and Promo Code. Expose required state on the actual client, date-time and Select controls. Keep the existing confirmation gates, restore/discard handlers, pricing order, orange dates and summary behavior. Implementation comments: new-rental-flow.css and BookingClientSection.tsx. No schema or live-record change.
